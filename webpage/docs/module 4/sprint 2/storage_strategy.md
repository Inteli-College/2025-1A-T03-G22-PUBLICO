# Sprint 17
## Sprint 17: Efficient Storage and Document Indexing Strategies
During this sprint, the main focus was the development and optimization of storage and indexing strategies for documents processed by the system — especially public notices and certificates. This stage was essential to ensure scalability, efficient querying, and low response time during the analysis and information retrieval process.

### Storage Structure
Initially, the use of a relational database (MySQL) was defined to store metadata and structured records, such as document information, processing results, and analysis history. However, for the extracted textual files (the full content of public notices and certificates), it was necessary to adopt a hybrid storage strategy.  
The original documents were stored in a file repository (dedicated storage or cloud service), while the processed texts — already converted and tokenized — were indexed in a vector search engine compatible with the RAG (Retrieval-Augmented Generation) pipeline. This approach enables semantic retrieval of relevant excerpts, allowing the LLM to access specific contextual information during response generation.

### Indexing and Retrieval
To optimize queries, a vector indexing process was implemented, in which each document is represented by numerical embeddings generated by the language model. These vectors are stored in a specialized database (such as FAISS, Pinecone, or Chroma), enabling searches based on semantic similarity rather than just keywords.  
Additionally, the documents were segmented into smaller chunks, ensuring retrieval granularity and reducing the model’s inference cost. Each chunk was indexed with metadata, such as title, section, and document type, facilitating filters and specific queries.

### Efficiency and Scalability
To ensure efficiency and scalability, the following measures were applied:  
- Compression and versioning of stored documents;  
- Pagination and result limiting in queries;  
- Caching of embeddings and frequent queries;  
- Resource usage monitoring and index optimization as data volume grows.  

These combined strategies ensure that the system can handle large volumes of documents while maintaining low response times and controlled costs, as well as enabling seamless integration with the RAG pipeline and the LLM model.
